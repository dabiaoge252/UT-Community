## 6. 必背清单（按顺序背）

### ① 一句话介绍项目
仿小红书的微服务项目。Java 17 + Spring Boot 3.0.2 + Spring Cloud Alibaba 2022.0.0，共 10 个微服务（网关 / 认证 / 用户 / 笔记 / 用户关系 / 计数 / 数据对齐 / 分布式ID / KV / OSS），自研 4 个 Starter。

### ② 服务清单与职责
| 服务 | 职责 |
|---|---|
| xiaohashu-gateway | 统一入口：路由、登录鉴权、权限校验 |
| xiaohashu-auth | 登录 / 注册 / 修改密码，签发 Token（Sa-Token） |
| xiaohashu-user | 用户信息、角色权限 |
| xiaohashu-note | 笔记发布 / 查询 / 更新 / 删除（缓存一致性 + MQ） |
| xiaohashu-user-relation | 关注 / 粉丝（Redis ZSET + Lua + MQ + 令牌桶） |
| xiaohashu-count | 计数消费（BufferTrigger 聚合）+ Redis Hash + 落库 |
| xiaohashu-data-align | 日增量落库 + XXL-JOB 分片对齐 |
| xiaohashu-distributed-id-generator | 美团 Leaf：号段 + 雪花 |
| xiaohashu-kv | Cassandra 键值存储（笔记内容） |
| xiaohashu-oss | 文件上传（Minio / 阿里云 OSS 策略） |

### ③ 一次完整请求链路
前端 → 网关(Gateway 鉴权) → auth 登录发 Token → Feign 调 user → 业务处理写 Redis/MySQL → 发 MQ → count 服务计数 → data-align 落增量 → 次日对齐。

### ④ 三大缓存问题 + 本项目解法
| 问题 | 本项目解法 |
|---|---|
| 缓存穿透 | 查库判空后写 `"null"` 占位，TTL 60s + 随机 60s |
| 缓存击穿 | Caffeine 本地缓存作为第一级（热点 key 兜底） |
| 缓存雪崩 | TTL 随机打散（保底 1 天 + 随机 0~1 天）+ 多级缓存 |
| 双写一致性 | 更新 DB 后删缓存 + 延时消息二次删（延迟双删） |

### ⑤ 数据对齐全链路（必讲，项目亮点）
```
当天：用户操作 → MQ → 消费者只记"变更记录"到 日期+分片 临时表（双 Bloom 去重）
次日：XXL-JOB 分片广播，每个实例处理一个分片
  → 从源表（t_following / t_note_like / t_note_collection / t_fans / t_note）count
  → 回写计数表（t_user_count / t_note_count）+ 更新 Redis Hash
  → 批量删除已处理临时记录
```
- 为什么：点赞/收藏/关注/发布是高频操作，实时写计数表写放大严重，改为"增量记录 + 次日源表重算"，保证**最终一致**
- 分片存储：`hashKey = id % tableShards`（shards 默认 3，Nacos 可动态刷新）
- 分片对齐：XXL-JOB 分片广播，实例数 = 分片数，互不冲突
- 兜底：各对齐任务查询前 `CREATE TABLE IF NOT EXISTS`，防建表任务漏跑报"表不存在"

### ⑥ MQ 消息链路（点赞 / 收藏 / 关注）
1. note / user-relation 业务操作 → 发 MQ（Tag 区分操作类型：Like/Unlike、Collect/UnCollect、Follow/Unfollow）
2. count 服务消费 → BufferTrigger 批量聚合 → Redis Hash 增减 + `ON DUPLICATE KEY UPDATE` 落库
3. data-align 消费同一批消息 → 双 Bloom 去重 → 写日增量临时表
4. 次日对齐任务重算回写

### ⑦ 幂等方案汇总
| 场景 | 方案 |
|---|---|
| 点赞 / 收藏 upsert | `INSERT ... ON DUPLICATE KEY UPDATE`（联合唯一索引 user_id+note_id） |
| 计数累加 | `ON DUPLICATE KEY UPDATE xx = xx + ?` |
| 日增量落库 | 布隆过滤器（双 Bloom）先查后写 + 唯一索引兜底 |
| 延迟双删 | 消息消费幂等（多删无害） |

### ⑧ 八股串联表（项目点 ↔ 八股题）
| 项目点 | 对应八股题 |
|---|---|
| 延迟双删 | 缓存与数据库一致性 |
| 空值缓存 / Caffeine / TTL 随机 | 缓存穿透 / 击穿 / 雪崩 |
| 布隆过滤器 + Lua | Redis 原子操作、海量数据判重 |
| 分片广播 | 分布式任务调度、分片并行处理 |
| ON DUPLICATE KEY UPDATE | MySQL 幂等、唯一索引 |
| BufferTrigger 批量聚合 | 流量削峰、批量处理 |
| 美团 Leaf 号段/雪花 | 分布式 ID 方案对比 |
| Starter 抽取 | Spring Boot 自动装配、SPI |

## 7. 复习技巧与面试策略

1. **讲项目用 STAR**：技术点别干背，套进踩过的真实问题（双 Bloom 改造就是现成故事：背景 → 现象 → 根因 → 方案 → 结果）。
2. **预判追问深挖点**（docs 里都有，重点准备）：
   - 布隆过滤器误判率怎么算？误判了会怎样？
   - 分片数与实例数不一致会怎样？（单实例 shardTotal=1 只处理分片 0）
   - 消息重复消费怎么保证幂等？
   - 为什么延迟双删要"延迟"？（主从同步 + 并发回填窗口）
   - 计数为什么不实时写库？
3. **动手跑一遍**：按 [业务流程.md](file:///d:/java/xiaohashu/xiaohashu/docs/03-业务流程/业务流程.md) 从登录到点赞收藏实际 Debug 一次，记住关键类名（AuthServiceImpl、NoteServiceImpl、CountNoteLikeConsumer、TodayNoteLikeIncrementData2DBConsumer、FollowingCountShardingXxlJob 等）。
4. **最后冲刺自检**：能不看文档，把"数据对齐""延迟双删""双 Bloom"三条链路各讲 2 分钟，即过关。
