## <a id="intro"></a>先读 30 秒：什么是"工具库"

写 Java 时你经常要干这些琐碎事：**判空**（集合空没空）、**拼字符串**（把列表拼成 `a,b,c`）、**生成随机数**、**对象转 JSON**、**读文件**……这些操作 JDK 自带的能力要么写起来啰嗦，要么容易踩坑（比如 `a.equals(b)` 遇到 a 为 null 直接崩）。

**工具库（三方工具类库）** 就是大佬们把这些"人人都要写的琐碎代码"提前写好、打包好的轮子。项目引入工具库后，一行代码就能完成原本要写 5~10 行的操作，而且人家已经帮你把边界情况（null、空串、纯空格）都处理好了。

一句话：**工具库 = 写代码的"快捷键"，让常用操作又短又安全**。下面是本项目实际用的 5 个，按"是什么 → 为什么用它 → 常用方法 → 项目真实示例"的顺序看即可。

## <a id="ch1"></a>一、Hutool（`cn.hutool.*`）

> **这是什么**：Hutool 是一个国产的"全能瑞士军刀"，集合操作、随机数、日期、加密、IO、JSON……什么都有，把 JDK 里难用、啰嗦的 API 全部封装成一行就能调用的简单方法。项目用 `hutool-all` 整体引入，相当于一整箱工具随便拿。
> **为什么项目要用它**：以本项目为例——发短信验证码需要一个 6 位随机数字，手写要 `Random` + 循环拼字符串，而 Hutool 一行 `RandomUtil.randomNumbers(6)` 就搞定，还不会出重复、越界的低级错误。

> 全能工具包，集合、随机数、日期、加密、IO 等应有尽有，项目中用 `hutool-all` 整体引入。

### 1.1 随机数 —— `cn.hutool.core.util.RandomUtil`

| 方法 | 作用 |
|------|------|
| `randomNumbers(int count)` | 生成指定长度的**纯数字**随机字符串（0-9） |

**项目示例**（生成短信登录验证码）：

[VerificationCodeServiceImpl.java](file:///d:/java/xiaohashu/xiaohashu/xiaohashu-auth/src/main/java/com/quanxiaoha/xiaohashu/auth/service/impl/VerificationCodeServiceImpl.java#L52)

```java
// 生成 6 位随机数字验证码
String verificationCode = RandomUtil.randomNumbers(6);
```

### 1.2 集合判断 —— `cn.hutool.core.collection.CollUtil`

| 方法 | 作用 |
|------|------|
| `isNotEmpty(Collection)` | 集合**既不为 null 也不为空**（size>0），省去手动判空 |
| `isNotEmpty(Map)` | Map 同理（CollUtil 同时支持集合与 Map 重载） |

**项目示例**（角色权限同步、网关权限加载）：

```java

if (CollUtil.isNotEmpty(roleDOS)) { ... }

// StpInterfaceImpl: 判断从 Redis 反序列化出的角色集合是否为空
if (CollUtil.isNotEmpty(userRoleKeys)) { ... }

// NoteServiceImpl: 校验笔记图片列表不能为空
Preconditions.checkArgument(CollUtil.isNotEmpty(imgUriList), "笔记图片不能为空");
```

## <a id="ch2"></a>二、Google Guava（`com.google.common.*`）

> **这是什么**：Guava 是 Google 开源的工具库，代码质量极高、被全行业广泛使用。本项目主要用到它三块能力：**前置条件校验**（`Preconditions`，参数不合法立刻报错）、**集合工厂**（`Lists`/`Maps`，少写 `new`）、以及第十节会提到的**限流**（`RateLimiter`）。
> **为什么项目要用它**：以参数校验为例——业务入口的参数（验证码不能为空、图片不能多于 8 张）需要"不满足就立刻抛异常"，`Preconditions.checkArgument(条件, "报错信息")` 一行搞定，而且抛出的异常会被项目全局异常处理器统一转成友好提示，比手写 `if (!xxx) { throw ... }` 更简洁统一。

> Google 开源工具库：前置校验、集合工厂、不可变集合、并发、缓存等。

### 2.1 前置条件校验 —— `com.google.common.base.Preconditions`

| 方法 | 作用 |
|------|------|
| `checkArgument(boolean expression, String errorMessage)` | 校验参数，**不满足时抛 `IllegalArgumentException`**，带错误信息 |

> ⚠️ 注意：本项目 auth / user 的 `GlobalExceptionHandler` 都有 `@ExceptionHandler({ IllegalArgumentException.class })`，Guava 校验不通过会被统一捕获并返回 `PARAM_NOT_VALID` 错误，所以可以放心在业务入口用。

**项目示例**：

```java
// AuthServiceImpl: 登录时校验验证码不能为空
Preconditions.checkArgument(StringUtils.isNotBlank(verificationCode), "验证码不能为空");

// UserServiceImpl: 更新用户信息时逐字段校验
Preconditions.checkArgument(ParamUtils.checkNickname(nickname), ResponseCodeEnum.NICK_NAME_VALID_FAIL.getErrorMessage());
Preconditions.checkArgument(ParamUtils.checkXiaohashuId(xiaohashuId), ResponseCodeEnum.XIAOHASHU_ID_VALID_FAIL.getErrorMessage());
Preconditions.checkArgument(SexEnum.isValid(sex), ResponseCodeEnum.SEX_VALID_FAIL.getErrorMessage());

// NoteServiceImpl: 校验图片数量上限
Preconditions.checkArgument(imgUriList.size() <= 8, "笔记图片不能多于 8 张");

// SnowflakeIDGenImpl: 校验雪花生辰等前置条件
Preconditions.checkArgument(timeGen() > twepoch, "Snowflake not support twepoch gt currentTime");
```

### 2.2 集合工厂 —— `com.google.common.collect.Lists` / `Maps`

| 方法 | 作用 |
|------|------|
| `Lists.newArrayList()` | 创建 `ArrayList`（等价 `new ArrayList<>()`） |
| `Maps.newHashMap()` | 创建 `HashMap`（等价 `new HashMap<>()`） |

**项目示例**：

```java
// PushRolePermissions2RedisRunner: 组装 角色key -> 权限列表
Map<String, List<String>> roleIdPermissionDOMap = Maps.newHashMap();
List<String> permissionKeys = Lists.newArrayList();

// StpInterfaceImpl: 聚合多个角色下的权限
List<String> permissions = Lists.newArrayList();

// SnowflakeZookeeperHolder: 存放 ip:port -> 节点序号
Map<String, Integer> nodeMap = Maps.newHashMap();
```

> 说明：`Lists.newArrayList()` / `Maps.newHashMap()` 与 `new ArrayList<>()` / `new HashMap<>()` 完全等价，只是更简短，并且还提供带容量等扩展重载。

## <a id="ch3"></a>三、Apache Commons Lang3（`org.apache.commons.lang3.StringUtils`）

> **这是什么**：Apache 基金会出的"字符串工具库"，专注处理字符串的判空、比较、拼接。本项目的 `StringUtils` 指的就是它（不是别的库）。
> **为什么项目要用它**：三个最实在的理由——① `isBlank` 连"纯空格"都帮你判了（JDK 的 `isEmpty` 判不了）；② `equals` 是 **null 安全**的，`a.equals(b)` 在 a 为 null 时直接崩（NPE），而 `StringUtils.equals(a, b)` 两个都是 null 也只返回 false 不报错；③ `join` 把集合拼成字符串一行搞定。这些正是项目里校验"头像不能为空"、比对"验证码是否正确"、拼接"图片链接列表"时反复用到的。

> 字符串工具类，项目中主要用于判空与拼接，比 JDK 原生 `==` 判断更安全简洁。

| 方法 | 作用 |
|------|------|
| `isBlank(String)` | 为 null、空串或纯空白字符 → true |
| `isNotBlank(String)` | `isBlank` 取反，常用作"非空才处理" |
| `equals(String a, String b)` | **null 安全**的字符串比较（替代 `a.equals(b)`，避免 NPE） |
| `join(Iterable, String)` | 用分隔符把集合拼成字符串 |

**项目示例**：

```java
// isBlank: 校验失败/为空场景
if (StringUtils.isBlank(avatar)) { throw new BizException(ResponseCodeEnum.UPLOAD_AVATAR_FAIL); }
if (StringUtils.isBlank(userId)) { chain.doFilter(request, response); return; }  // 请求头无 userId 直接放行

// isNotBlank: 有值才处理（更新用户信息只更新非空字段）
if (StringUtils.isNotBlank(nickname)) { ... }
if (StringUtils.isNotBlank(introduction)) { ... }

// equals: 按配置值匹配存储类型 / 告警类型（null 安全）
if (StringUtils.equals(strategyType, "minio")) { ... }      // FileStrategyFactory
if (StringUtils.equals("sms", alarmType)) { ... }           // AlarmConfig
if (!StringUtils.equals(verificationCode, sentCode)) { ... } // AuthServiceImpl 验证码比对

// join: 图片 URL 列表拼接成逗号分隔字符串
String imgUris = StringUtils.join(imgUriList, ",");          // NoteServiceImpl
```

> 对比记忆：`isBlank` 比 `isEmpty` 多判了**纯空白字符**（空格、tab 等）。

## <a id="ch5"></a>五、TransmittableThreadLocal（`com.alibaba.ttl`）

> **这是什么**：先认识它的"爸爸" **ThreadLocal**：每个线程一个"独立储物柜"，存进去的数据只有当前线程能取。它的"老大难"问题：线程池里的线程是**复用的**，A 请求存了数据，线程还给池子后 B 请求可能拿到同一个线程，A 的数据就串给 B 了。**TTL（TransmittableThreadLocal）** 是阿里巴巴出的增强版：当新任务提交到线程池时，自动把当前线程的"储物柜内容"复制一份透传给执行任务的那个线程，用完再清理，既传递了数据又不会串线。
> **为什么项目要用它**：本项目要把"当前登录用户 ID"从网关一路传到最底层的业务代码（全链路透传）。登录用户的上下文（`LoginUserContextHolder`）就用 TTL 存，这样 `AuthServiceImpl` 用线程池异步打日志时，异步线程里依然能取到用户 ID。

> 阿里巴巴 TTL，是 `ThreadLocal` 的增强版：**线程池场景下也能把线程局部变量透传给子线程**。

| 方法 | 作用 |
|------|------|
| `TransmittableThreadLocal.withInitial(Supplier)` | 创建带初始值的 TTL 变量 |

**项目示例**（登录用户上下文，这是本项目 userId 全链路透传的核心）：

[LoginUserContextHolder.java](file:///d:/java/xiaohashu/xiaohashu/xiaoha-framework/xiaoha-spring-boot-starter-biz-context/src/main/java/com/quanxiaoha/xiaohashu/framework/biz/context/holder/LoginUserContextHolder.java#L24-L25)

```java
private static final ThreadLocal<Map<String, Object>> LOGIN_USER_CONTEXT_THREAD_LOCAL
        = TransmittableThreadLocal.withInitial(HashMap::new);
```

**配套用法**（配合使用，避免内存泄漏）：

```java
LoginUserContextHolder.setUserId(userId);   // 存入上下文
...                                          // 业务代码 / 异步线程都能取到
LoginUserContextHolder.remove();             // finally 中清理（见 HeaderUserId2ContextFilter）
```

> 场景示例：`AuthServiceImpl` 登出时用线程池异步打日志，异步线程中仍能通过 `LoginUserContextHolder.getUserId()` 取到用户 ID，正是 TTL 的作用。

## <a id="ch6"></a>六、使用小贴士

> **这是什么**：前五节看完了，这节把最容易踩的 4 个坑 + 1 个历史遗留问题集中提醒一遍，写代码时对照自查即可。

1. **Guava `checkArgument` 抛的是 `IllegalArgumentException`**，依赖各服务 `GlobalExceptionHandler` 捕获转成统一响应（`PARAM_NOT_VALID`），业务方法里无需 try-catch。
2. **判空优先用工具方法**：集合用 `CollUtil.isNotEmpty`，字符串用 `StringUtils.isNotBlank`，比手写 `!= null && !xxx.isEmpty()` 更安全简洁。
3. **字符串比较用 `StringUtils.equals`**，避免 `a.equals(b)` 在 `a` 为 null 时 NPE。
4. **TTL 用完必须 `remove()`**，否则线程池复用线程会导致用户信息串线/内存泄漏（项目已在 Filter 的 finally 中处理）。

> ⚠️ 一个小坑：网关的 [StpInterfaceImpl.java](file:///d:/java/xiaohashu/xiaohashu/xiaohashu-gateway/src/main/java/com/quanxiaoha/xiaohashu/gateway/auth/StpInterfaceImpl.java#L5) 引入了 Nacos 内部 shaded 的 Guava（`com.alibaba.nacos.shaded.com.google.common.collect.Lists`）。功能正常，但不推荐依赖框架内部的 shaded 类，建议统一改为项目自带的 `com.google.common.collect.Lists`，避免升级 Nacos 后编译错误。
