### 1.3 聚合工程与版本管理（根 pom）

根聚合工程 [pom.xml](file:///d:/java/xiaohashu/xiaohashu/pom.xml)：

- `packaging=pom`，通过 `<modules>` 聚合所有子模块；
- `<properties>` 中定义 `revision=0.0.1-SNAPSHOT`，各子模块统一用 `${revision}` 作为版本号；
- `<dependencyManagement>` 统一管理依赖版本（含自研模块：`xiaoha-common`、`xiaohashu-oss-api`、`xiaohashu-user-api`、`xiaohashu-note-api`、`xiaohashu-user-relation-api`、`xiaohashu-count-api`、`xiaohashu-kv-api`、`xiaohashu-distributed-id-generator-api` 及各 Starter），子模块引入时无需写版本号；
- 配置 `flatten-maven-plugin`，解决子模块打包时无法解析 `${revision}` 的问题。

```
    ├──▶ xiaohashu-user   （用户注册/信息更新/密码更新）
    │
    ├──▶ xiaohashu-note   （笔记发布/查询/更新/删除/可见性/置顶）
    │         │  ├─ RPC: UserFeignApi（查作者）
    │         │  ├─ RPC: KeyValueFeignApi（存/取/删正文）
    │         │  ├─ RPC: DistributedIdGeneratorFeignApi（生成笔记 ID）
    │         │  ▼
    │         │  ├─ xiaohashu-user-biz
    │         │  ├─ xiaohashu-kv-biz
    │         │  └─ xiaohashu-distributed-id-generator-biz
    │         │  └─ RocketMQ（广播删本地缓存 / 延时删 Redis 缓存）
    │
    ├──▶ xiaohashu-user-relation （关注/取关）
    │         │  RPC: UserFeignApi（校验被关注用户存在）
    │         │  RocketMQ: FollowUnfollowTopic（异步落库 + 令牌桶削峰）
    │         │  RocketMQ: CountFansTopic / CountFollowingTopic（通知计数服务）
    │         ▼
    │         ├─ xiaohashu-user-biz
    │         └─ RocketMQ
    │
    ├──▶ xiaohashu-count   （粉丝数 / 关注数统计）
    │         │  RocketMQ: CountFansTopic（BufferTrigger 聚合粉丝数）
    │         │  RocketMQ: CountFollowingTopic（关注数直更）
    │         │  RocketMQ: CountFans2DBTopic / CountFollowing2DBTopic（落库削峰）
    │         ▼
    │         └─ RocketMQ → MySQL（t_user_count / t_note_count）
    │
    ├──▶ xiaohashu-data-align （数据对齐：日增量落库 + 次日分片对齐）
    │         │  RocketMQ: CountNoteLikeTopic / CountNoteCollectTopic（来自 note 转发）
    │         │  RocketMQ: CountFollowingTopic（来自 user-relation）
    │         │  RocketMQ: NoteOperateTopic（来自 note，发布/删除）
    │         ▼
    │         ├─ 双 Bloom 去重 → 写 日期+分片 临时表
    │         └─ XXL-JOB 分片广播 → 源表重算 → 回写 t_user_count / t_note_count + Redis
    │
    └──▶ xiaohashu-kv     （笔记内容增删查，Feign 接口已就绪：KeyValueFeignApi）
```

关键透传链路：

```
网关 AddUserId2HeaderFilter 将登录用户 ID 写入请求头 userId
    → 下游服务 HeaderUserId2ContextFilter 解析 userId 存入 ThreadLocal
    → Feign 调用时 FeignRequestInterceptor 再把 userId 写回请求头透传
```

## 二、模块与包详解

---

### 2.1 xiaoha-framework（平台基础设施层）

> 定位：封装通用功能（工具类、切面、过滤器、序列化等），供各业务模块"拿来即用"。

> 小提示：`xiaoha-framework/pom.xml` 的 `<modules>` 只聚合了 common、operationlog、biz-context 三个模块，`xiaoha-spring-boot-starter-jackson` 是在根聚合 pom 中单独注册的（`xiaoha-framework/xiaoha-spring-boot-starter-jackson`）。

#### 2.1.1 xiaoha-common（通用模块）

> 定位：平台通用类库，无 Spring Boot 自动装配，供所有模块依赖。

| 包 | 职责 | 关键类 |
|----|------|--------|
| `constant` | 全局常量 | `GlobalConstants`（userId 请求头常量）、`DateConstants`（日期格式化模板） |
| `enums` | 通用枚举 | `DeletedEnum`（逻辑删除 是/否）、`StatusEnum`（状态 启用/禁用） |
| `exception` | 异常体系 | `BaseExceptionInterface`（异常码/异常信息接口）、`BizException`（业务异常） |
| `response` | 统一响应体 | `Response<T>`（success/fail 静态工厂，微服务间传输） |
| `util` | 工具类 | `JsonUtils`（Jackson 封装）、`ParamUtils`（昵称/小哈书号/长度校验） |
| `validator` | 自定义校验 | `PhoneNumber`（手机号校验注解）、`PhoneNumberValidator`（11 位数字校验实现） |

#### 2.1.2 xiaoha-spring-boot-starter-biz-operationlog（接口操作日志组件）

> 定位：基于 AOP 的操作日志 Starter，凡标注 `@ApiOperationLog` 的接口自动打印入参、出参、耗时。

| 包 | 职责 | 关键类 |
|----|------|--------|
| `aspect` | 注解与切面 | `ApiOperationLog`（方法级注解，含 description 描述）、`ApiOperationLogAspect`（环绕通知打印日志） |
| `config` | 自动配置 | `ApiOperationLogAutoConfiguration`（注册切面 Bean） |

通过 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 注册自动配置。

#### 2.1.3 xiaoha-spring-boot-starter-biz-context（登录用户上下文组件）

> 定位：把网关透传的 `userId` 请求头解析到本地上下文，并在 Feign 调用时透传，供业务代码 `LoginUserContextHolder.getUserId()` 获取当前登录用户。

| 包 | 职责 | 关键类 |
|----|------|--------|
| `config` | 自动配置 | `ContextAutoConfiguration`（注册过滤器）、`FeignContextAutoConfiguration`（注册 Feign 拦截器） |
| `filter` | 请求过滤器 | `HeaderUserId2ContextFilter`（解析请求头 userId → ThreadLocal，finally 清理防泄漏） |
| `holder` | 上下文持有者 | `LoginUserContextHolder`（基于 `TransmittableThreadLocal`，支持线程池传递） |
| `interceptor` | Feign 拦截器 | `FeignRequestInterceptor`（Feign 请求前把 userId 写入请求头） |

#### 2.1.4 xiaoha-spring-boot-starter-jackson（Jackson 序列化组件）

> 定位：全局定制 ObjectMapper，统一时间格式与序列化规则。

| 包 | 职责 | 关键类 |
|----|------|--------|
| `config` | 自动配置 | `JacksonAutoConfiguration`（时间格式 `yyyy-MM-dd HH:mm:ss` 等、时区 Asia/Shanghai、忽略未知属性，并初始化 `JsonUtils`） |

---

### 2.2 xiaohashu-gateway（网关服务）

> 定位：微服务统一入口，基于 Spring Cloud Gateway 响应式编程。负责路由转发、登录态校验、接口权限校验，并把登录用户 ID 透传给下游服务。

| 包 | 职责 | 关键类 |
|----|------|--------|
| `auth` | Sa-Token 鉴权 | `SaTokenConfigure`（注册 `SaReactorFilter` 全局过滤器，配置登录校验与权限校验路由）、`StpInterfaceImpl`（实现 `StpInterface`，从 Redis 查询用户角色/权限列表） |
| `config` | 配置类 | `RedisTemplateConfig`（String 序列化 RedisTemplate） |
| `constant` | 常量 | `RedisKeyConstants`（构建 `user:roles:`、`role:permissions:` key） |
| `enums` | 枚举 | `ResponseCodeEnum`（响应码） |
| `exception` | 异常处理 | `GlobalExceptionHandler`（实现 `ErrorWebExceptionHandler`，未登录/无权限返回 401，其他返回系统错误） |
| `filter` | 网关过滤器 | `AddUserId2HeaderFilter`（实现 `GlobalFilter`，登录用户 ID 写入请求头 `userId` 透传下游） |

### 2.3 xiaohashu-auth（认证服务）

> 定位：负责处理所有与用户身份验证相关的操作。它主要确保用户身份的真实性和合法性，管理用户登录、登出以及令牌（token）的生成与密码加密等。

| 包 | 职责 | 关键类 |
|----|------|--------|
| `controller` | HTTP 接口层 | `AuthController`（登录/注册、登出、修改密码）、`VerificationCodeController`（发送短信验证码）、`TestController`（测试：Nacos 动态配置、告警触发） |
| `service` | 业务逻辑层 | `AuthService` / `AuthServiceImpl`（验证码登录 + 密码登录、Sa-Token 签发 token、登出、改密）、`VerificationCodeService` / `VerificationCodeServiceImpl`（生成 6 位验证码、3 分钟过期、发送频率限制、异步调用阿里云短信） |
| `rpc` | 远程调用层 | `UserRpcService`（封装 `UserFeignApi`，调用用户服务：注册、按手机号查询、更新密码） |
| `model.vo` | 入参对象 | `user/UserLoginReqVO`（手机号、验证码、密码、登录类型）、`user/UpdatePasswordReqVO`（新密码）、`verificationcode/SendVerificationCodeReqVO`（发送验证码入参） |
| `enums` | 枚举 | `LoginTypeEnum`（登录方式：1 验证码 / 2 密码）、`ResponseCodeEnum`（响应码） |
| `config` | 配置类 | `RedisTemplateConfig`（String key + Jackson value 序列化）、`PasswordEncoderConfig`（BCrypt 密码加密）、`ThreadPoolConfig`（`taskExecutor` 线程池，异步发送短信） |
| `constant` | 常量 | `RedisKeyConstants`（验证码 key 构建）、`RoleConstants`（角色常量） |
| `sms` | 短信服务 | `AliyunAccessKeyProperties`（阿里云密钥配置）、`AliyunSmsClientConfig`（构建短信客户端）、`AliyunSmsHelper`（发送短信工具） |
| `alarm` | 告警策略 | `AlarmInterface`（告警接口）、`AlarmConfig`（按配置 `alarm.type` 动态选择实现，`@RefreshScope` 支持动态刷新）、`impl/MailAlarmHelper`（邮件告警）、`impl/SmsAlarmHelper`（短信告警） |
| `exception` | 异常处理 | `GlobalExceptionHandler`（`@ControllerAdvice`，处理业务异常、参数校验异常、IllegalArgumentException 等） |

> 备注：`xiaohashu-auth` 的 `resources/mapper/` 下残留了 5 个旧的 Mapper XML 文件，但当前源码中已无对应的 Mapper 接口，属于历史遗留，不影响功能。

### 2.6 xiaohashu-distributed-id-generator（分布式 ID 生成服务）

> 定位：基于**美团 Leaf** 的分布式 ID 生成服务，提供"号段模式（Segment）"与"雪花模式（Snowflake）"两种 ID 生成算法，供各业务服务通过 Feign 获取全局唯一 ID（当前用户服务注册时用它生成小哈书 ID / 用户 ID）。

#### 2.6.1 xiaohashu-distributed-id-generator-api（RPC 层）

| 包 | 职责 | 关键类 |
|----|------|--------|

### 2.11 xiaohashu-data-align（数据对齐服务）

> 定位：把当天发生的计数相关变更（点赞 / 收藏 / 关注 / 发布）落库到**按日期 + 分片**的日增量临时表，次日由 XXL-JOB **分片广播**任务从源表重算准确计数并回写计数表与 Redis，保证计数**最终一致**。覆盖 **7 类计数**：关注数、粉丝数、笔记点赞数、笔记收藏数、用户获赞数、用户获收藏数、用户发布笔记数。

| 包 | 职责 | 关键类 |
|----|------|--------|
| `consumer` | MQ 消费者（当天写日增量临时表） | `TodayNoteLikeIncrementData2DBConsumer`（笔记点赞）、`TodayNoteCollectIncrementData2DBConsumer`（笔记收藏）、`TodayUserFollowIncrementData2DBConsumer`（关注 / 粉丝）、`TodayNotePublishIncrementData2DBConsumer`（发布 / 删除）——**双 Bloom**（笔记 ID + 发布者 ID 各自独立）幂等去重后，按 `id % shards` 写临时表 |

| `config` | 配置类 | `TableConfig`（`table.shards` 分片数，`@RefreshScope` Nacos 动态刷新）、`XxlJobConfig` / `XxlJobProperties`（XXL-JOB 执行器接入）、`RocketMQConfig`、`RedisTemplateConfig` |
| `constant` | 常量 | `MQConstants`（消费的 Topic）、`RedisKeyConstants`（双 Bloom key 与计数 Hash field）、`TableConstants`（临时表名后缀构建） |

> 1. **写侧（当天）**：note / user-relation 产生变更 → MQ → 消费者用**双 Bloom** 判断"当天是否已落库"（先落库、后登记，`BF.ADD` 只在 insert 成功后执行）→ 未落库则写入 `t_data_align_*_count_temp_{日期}_{分片}` 临时表；
> 2. **读侧（次日）**：7 个分片广播对齐任务读取各自分片的临时表 → 从源表（`t_following` / `t_fans` / `t_note_like` / `t_note_collection` / `t_note`）重新 count → 回写 `t_user_count` / `t_note_count` 并更新 Redis Hash（`count:user:{id}` / `count:note:{id}`）→ 批量删除已处理记录；

## 三、关键设计要点

1. **统一版本管理**：根 pom 通过 `${revision}` + `dependencyManagement` + flatten 插件管理所有模块版本，子模块依赖无需写版本号。
2. **Starter 抽取**：凡是需要"引入即自动生效"的能力（日志切面、上下文过滤器、Jackson 配置）都封装为 Spring Boot Starter，通过 `AutoConfiguration.imports` 注册。
3. **RPC 分层**：每个业务服务拆分为 `*-api`（Feign 接口 + DTO）与 `*-biz`（实现）两个模块，接口契约与实现解耦。
4. **userId 全链路透传**：网关 → 请求头 → 上下文 Starter（ThreadLocal）→ Feign 拦截器 → 下游服务，业务代码统一通过 `LoginUserContextHolder` 获取当前用户。
5. **策略模式**：OSS 存储（Minio / 阿里云 OSS）、告警方式（短信 / 邮件）均采用"接口 + 工厂 + 配置驱动"实现，并支持 Nacos 动态刷新。
6. **分布式 ID（美团 Leaf）**：号段模式采用"DB 预取号段 + 双 Segment 切换 + 动态步长"，雪花模式通过 ZooKeeper 分配 workerId；用户注册生成用户 ID / 小哈书号已从 Redis 自增切换为该服务，保证全局唯一且高性能。
7. **KV 存储（Cassandra）**：笔记内容等大文本数据走 Cassandra（`xiaohashu-kv` 服务），与 MySQL 关系型数据分工存储，按需扩展。
8. **消息队列（RocketMQ）**：用于异步解耦与缓存一致性——笔记更新用**广播模式**删各实例本地缓存、用**延时消息（延迟双删）**二次删 Redis；关注/取关用**集群消费**异步落库。延时消息只能选预设 18 级档位。
9. **令牌桶限流（Guava RateLimiter）**：`FollowUnfollowConsumer` 消费前 `acquire()` 削峰，速率由 Nacos 配置 + `@RefreshScope` 动态调整（重建令牌桶）；单机内存限流，多实例各自独立。
10. **关注关系存储**：Redis ZSET（score=关注时间）承载"热点读 + 原子判断"（Lua 脚本保证判重/上限/添加原子性），MySQL `t_following` / `t_fans` 持久化兜底，MQ 异步落库削峰。
11. **计数（Redis Hash + 两级 MQ）**：`xiaohashu-count` 服务承接粉丝数/关注数——先写 Redis Hash（`count:user:{id}` 的 `fansTotal` / `followingTotal`，`increment` 加减），再转发二级 MQ 落库；粉丝数高频消息用 **BufferTrigger 聚合**（1 秒 / 1000 条触发，按目标用户合并净变化量），关注数频率低直更；落库消费者令牌桶削峰 + `insertOrUpdate`。
12. **Redis Pipeline 批量写**：批量查用户后回填缓存（`UserServiceImpl.findByIds`）用 `executePipelined` 把多条 set 打包成一次网络请求，减少 RTT；Pipeline 只管"批量快写"不保证原子性，与 Lua 脚本（保证原子）分工明确。
13. **数据对齐（分片存储 + 分片广播 + 双 Bloom）**：计数不实时写库（写放大），当天把"谁变了"写入 日期+分片 临时表（**双 Bloom**——笔记 ID / 发布者 ID 各自独立，先落库后登记，幂等去重），次日 XXL-JOB **分片广播**从源表重算回写计数表与 Redis，保证最终一致；临时表每日由建表任务预创建、超一月由删表任务清理，对齐任务查询前兜底建表。
