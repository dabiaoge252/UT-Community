## 1. 找不到符号 log（@Slf4j 不生效）

**报错信息**

```
java: 找不到符号
符号:   变量 log
位置: 类 com.quanxiaoha.framework.biz.operationlog.aspect.ApiOperationLogAspect
```

**根因**

Maven 命令行编译正常，但 IntelliJ IDEA 内置编译器没有处理 Lombok 注解：
- 未安装 Lombok 插件
- 未勾选 `Enable annotation processing`

**解决办法**

1. `File → Settings → Plugins` 安装 **Lombok** 插件并重启
2. `Settings → Build, Execution, Deployment → Compiler → Annotation Processors` 勾选 **Enable annotation processing**
3. `Build → Rebuild Project`

## 2. 凭据链加载失败（CredentialsException）

**报错信息**

```
com.aliyun.credentials.exception.CredentialException: Unable to load credentials from any of the providers in the chain:
[SystemPropertiesCredentialsProvider: System property alibabacloud.accessKeyId cannot be empty.,
EnvironmentVariableCredentialsProvider: Environment variable accessKeyId cannot be empty., ...]
```

**根因**

`new com.aliyun.credentials.Client()`（凭据链）按固定顺序查找 AK/SK（系统属性 → 环境变量 → 配置文件 → ECS 元数据），本机都没有；而实际 AK/SK 配置在 `application.yml` 中，凭据链根本不读。

**解决办法**

改用 `setAccessKeyId() / setAccessKeySecret()` 显式传 AK/SK：

```java
Config config = new Config()
        .setCredential(credential)
        .setAccessKeyId(accessKeyId)
        .setAccessKeySecret(accessKeySecret);
```

## 3. 短信接口返回成功但手机收不到短信

**报错信息**

```
{"code":"isv.INVALID_PARAMETERS","message":"模版变量min内容非法","success":false}
```

**根因**

- 模板 `SMS_154950909`（阿里云短信测试）属于**短信服务（dysmsapi）**，而代码调用的是**号码认证服务（dypnsapi）**的 `SendSmsVerifyCode`，两套模板体系不一致，模板变量校验不通过
- 代码只 catch 异常，没有检查 `response.body.success`，业务失败也返回了成功

**解决办法**

- 确认模板与调用 API 所属服务一致（`SendSms` → 短信服务；`SendSmsVerifyCode` → 号码认证服务）
- 调用后判断 `response.body.success`，失败时记录 `code/message` 并返回失败

## 4. 短信接口 404：Specified api is not found

**报错信息**

```
com.aliyun.tea.TeaException: code: 404, Specified api is not found, please check your url and method.
```

**根因**

endpoint 与调用的 API 不属于同一个服务（如 endpoint 配的是 `dysmsapi.aliyuncs.com`，但调用的是 dypnsapi 的 `sendSmsVerifyCodeWithOptions`）。`SendSmsVerifyCode` 只存在于 `dypnsapi.aliyuncs.com` 下。

**解决办法**

保证 endpoint 与 API 所属服务匹配：号码认证服务 → `dypnsapi.aliyuncs.com`；短信服务 → `dysmsapi.aliyuncs.com`。

## 5. NoClassDefFoundError: UserServiceImpl$1

**报错信息**

```
jakarta.servlet.ServletException: Handler dispatch failed:
java.lang.NoClassDefFoundError: com/quanxiaoha/xiaohashu/auth/service/impl/UserServiceImpl$1
```

**根因**

源码与 `target/classes` 不同步（IDEA 增量编译残留 / 代码回退后未重建），匿名内部类（`$1`）的编译产物缺失，运行时加载不到。

**解决办法**

`Build → Rebuild Project` 彻底重建，确保 target 与源码一致。

## 6. 启动失败：无法读取 JacksonAutoConfiguration

**报错信息**

```
java.lang.IllegalStateException: Unable to read meta-data for class com.quanxiaoha.framework.jackson.config.JacksonAutoConfiguration
Caused by: java.io.FileNotFoundException: class path resource [com/quanxiaoha/framework/jackson/config/JacksonAutoConfiguration.class] cannot be opened because it does not exist
```

**根因**

`xiaoha-spring-boot-starter-jackson` 的 `target/classes` 为空，`.class` 文件全部丢失；但 `AutoConfiguration.imports` 里注册了该类，Spring 启动扫描时找不到类文件。

**解决办法**

重新编译对应模块：

```bash
mvn compile -pl xiaohashu-auth -am
```

或在 IDEA 执行 `Rebuild Project`，确保所有 starter 的 `target/classes` 有 `.class` 文件。

## 7. 文件上传 400 Bad Request

**报错信息**

```json
{
  "timestamp": "2026-08-02T09:15:03.796+00:00",
  "status": 400,
  "error": "Bad Request",
  "path": "/file/upload"
}
```

**根因**

手动设置了 `Content-Type: application/x-www-form-urlencoded`，但接口要求 `multipart/form-data`：

```java
@PostMapping(value = "/upload", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
public Response<?> uploadFile(@RequestPart(value = "file") MultipartFile file)
```

**解决办法**

- **删掉**请求头里手动加的 `Content-Type`
- Postman Body 类型选 **form-data**
- 字段 `KEY = file`，类型切到 **File**，选择文件
- 让 Postman 自动生成 `Content-Type: multipart/form-data; boundary=...`

curl 方式：

```bash
curl.exe -X POST "http://localhost:8081/file/upload" -F "file=@D:\图片路径\xxx.jpg"
```

## 8. 文件上传：Required part 'file' is not present

**报错信息**

```
org.springframework.web.multipart.support.MissingServletRequestPartException:
Required part 'file' is not present.
```

**根因**

multipart 请求已进入（Content-Type 问题已解决），但请求体中没有名为 `file` 的 part。常见原因：
- Body 类型实际不是 form-data（如仍选 x-www-form-urlencoded）
- KEY 名不是严格等于 `file`（有空格 / 大小写不符）
- 该字段行的"启用"checkbox 未勾选
- VALUE 没切到 File 类型、没选文件

**解决办法**

依次检查：Body = form-data → KEY = `file`（无空格）→ 左侧勾选启用 → 右侧类型 File → Select Files 选择图片。

## 9. 接口报 401：未按照指定前缀提交 token

**报错信息**

```json
{
  "success": false,
  "message": "未按照指定前缀提交 token，prefix=Bearer",
  "errorCode": "401"
}
```

**根因**

Sa-Token 配置了 `token-prefix: Bearer`，请求必须带 `Authorization` 请求头且以 `Bearer ` 前缀开头。测试时未带 token 或前缀不对。

**解决办法**

1. 先调登录接口拿 token
2. 请求头加：

```
Authorization: Bearer <登录返回的token>
```

## 10. OSS 上传 AccessDenied：bucket 地域与 endpoint 不匹配

**报错信息**

```
[ErrorCode]: AccessDenied
The bucket you are attempting to access must be addressed using the specified endpoint.
Please send all future requests to this endpoint.
<HostId>xiaohashu.oss-cn-beijing.aliyuncs.com</HostId>
<Endpoint>oss-cn-hangzhou.aliyuncs.com</Endpoint>
```

**根因**

配置的 endpoint 地域（`oss-cn-beijing`）与 bucket 实际创建地域（杭州 `oss-cn-hangzhou`）不一致。OSS 要求请求必须发往 bucket 所在地域的 endpoint。

**解决办法**

将 [application-dev.yml](file:///D:/java/xiaohashu/xiaohashu/xiaohashu-oss/xiaohashu-oss-biz/src/main/resources/config/application-dev.yml) 中 `aliyun-oss.endpoint` 改为 bucket 实际地域（本例改为 `oss-cn-hangzhou.aliyuncs.com`），重新编译重启。

**备注**

bucket 名称目前硬编码在 `FileServiceImpl.BUCKET_NAME`，后可改为从 `storage.aliyun-oss.bucket` / `storage.minio.bucket` 配置读取（已实现动态选择）。

## 11. Starter 组件未注入（biz-context）

**报错信息**

auth 模块引用 `com.quanxiaoha.framework.biz.context.holder.LoginUserContextHolder` 报"找不到符号"，Spring 启动也找不到自动配置类。

**根因（两个叠加）**

1. **模块从未构建**：`xiaoha-framework/pom.xml` 的 `<modules>` 里漏注册 `xiaoha-spring-boot-starter-biz-context`，本地仓库无 jar，依赖无法解析
2. **包名不一致**：模块内实际包名是 `com.quanxiaoha.context.*`，但 `AutoConfiguration.imports` 和业务代码 import 的是 `com.quanxiaoha.framework.biz.context.*`

**解决办法**

1. 在聚合 pom `<modules>` 中注册该模块
2. 统一三处包名（源码 / imports 文件 / 业务代码 import），全用 `com.quanxiaoha.framework.biz.context.*`
3. 重新构建：`mvn install -pl xiaoha-framework/xiaoha-spring-boot-starter-biz-context -am`

## 12. 修改配置不生效（target 里是旧配置）

**报错现象**

改了 `storage.type`（如改为 minio），重启后上传仍走 aliyun。

**根因**

Spring Boot 启动时加载的是 **`target/classes` 下编译产物**中的配置文件，而不是 `src/main/resources` 源码。改源码后未重新编译，target 里还是旧配置。

**解决办法**

```bash
mvn clean compile -pl xiaohashu-oss/xiaohashu-oss-biz -am
```

或 IDEA 中 `Build → Rebuild Project`，再重启服务。

**排查技巧**：出问题时对比 `src/main/resources` 与 `target/classes` 中同名 yml 是否一致。

## 13. @RefreshScope 动态刷新不生效

**报错现象**

配置类标了 `@RefreshScope`，但从 Nacos 修改配置后 Bean 不重建、配置不刷新。

**根因**

`@RefreshScope` 只是提供刷新机制，**触发刷新的信号来自 Nacos 配置中心的 `RefreshEvent`**。而模块：
- 未引入 `spring-cloud-starter-alibaba-nacos-config`（只有 `nacos-discovery`）
- `bootstrap.yml` 里只配置了 `nacos.discovery`，没有 `nacos.config`

没有配置中心，刷新事件永远不会触发。

**解决办法**

1. 引入依赖：

```xml
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-config</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-bootstrap</artifactId>
</dependency>
```

2. `bootstrap.yml` 配置 `nacos.config`（server-addr / namespace / group / file-extension / refresh-enabled: true）
3. Nacos 控制台创建对应 Data ID 的配置
4. 属性类用 `@ConfigurationProperties(prefix="xxx")` + `@RefreshScope`，`@Bean` 方法同样标注

详细步骤见《Nacos配置动态Bean指南.md》。

## 14. RocketMQ 广播消息：只有收到请求的实例有"发送成功"日志

**报错现象**

部署了 3 个 note-biz 实例，调用更新笔记接口后，只有一个实例日志出现：

```
====> MQ：删除笔记本地缓存发送成功, 耗时: 96ms
```

其余两个实例没有这条日志，怀疑它们没收到广播消息、本地缓存没删。

**根因**

- "发送成功"是**生产者**日志（`NoteServiceImpl.updateNote` 中 `syncSend` 之后打印），只有**收到 HTTP 请求的那个实例**才会出现——网关只把请求路由到一个实例，**这是正常现象**；
- 广播模式（`BROADCASTING`）下，同消费组 `xiaohashu_group` 的**每个实例都会消费同一条消息**，其余实例应该打印的是**消费者**日志（`DeleteNoteLocalCacheConsumer` 的 `## 消费者消费成功, noteId: xxx`）。

**解决办法**

1. 先分清日志角色：
   - 生产者日志 `MQ：删除笔记本地缓存发送成功` → **仅请求落到的实例**
   - 消费者日志 `## 消费者消费成功, noteId: xxx` → **所有实例都应出现**
2. 若其他实例连消费者日志都没有，依次排查：
   - 各实例 `rocketmq.name-server` 是否都指向同一 NameServer（如 `127.0.0.1:9876`）
   - 实例是否在 MQ 宕机期间启动（MQ 恢复后一般会自动重连，必要时重启实例）
   - 用 `mqadmin consumerProgress -g xiaohashu_group -t DeleteNoteLocalCacheTopic` 确认消费者注册与消费情况

**排查技巧**：先区分"生产者日志"与"消费者日志"，确认在正确的实例上看正确的日志，避免误判。

## 15. XXL-Job 任务报 job handler not found（@RefreshScope 冲突）

**报错现象**

xxl-job-admin 调度日志：

```
code: 500
msg: job handler [createTableJobHandler] not found.
```

执行器只启动了一个实例、`@Component` + `@XxlJob("createTableJobHandler")` 写法也正确，但任务一直失败；服务启动日志里**看不到** `register jobhandler success, name:createTableJobHandler` 这行注册日志。

**根因**

`@RefreshScope` 加在了 Job 类上。XXL-Job 的 `XxlJobSpringExecutor` 注册 handler 的流程是：

1. `applicationContext.getBeansWithAnnotation(XxlJob.class)` 找到带注解的 Bean
2. 反射 `bean.getClass().getDeclaredMethods()` 找方法上的 `@XxlJob` 注解

而 `@RefreshScope` 会把该 Bean 替换成 **CGLIB 代理对象**（为了支持配置热刷新），第 2 步拿到的是代理类，代理类生成的方法**不携带 `@XxlJob` 注解** → handler 被静默跳过，任务调度时执行器侧就报 `job handler not found`。

> 验证过的现象：同一个 Job 类，加 `@RefreshScope` 前注册正常（日志有 register success），加上后立刻注册不上——即"加了动态刷新，handler 就没了"。

**解决办法**

1. **Job 类上去掉 `@RefreshScope`**（只保留 `@Component` + `@XxlJob`）
2. 需要动态刷新的配置（如 `@Value("${table.shards}")`）**单独放到一个 `@RefreshScope` 的配置类**（如 `TableConfig`），Job 类注入该配置类使用：

```java
@Component
@RefreshScope
@Data
public class TableConfig {
    @Value("${table.shards}")
    private int shards;
}
```

```java
@Component   // Job 类不再加 @RefreshScope
public class CreateTableXxlJob {
    @Resource
    private TableConfig tableConfig; // 动态配置注入，Nacos 改配置自动生效
    ...
}
```

3. 重启服务，确认启动日志出现 `xxl-job register jobhandler success, name:createTableJobHandler`
4. 再到 admin 触发任务验证

**排查技巧**：
- 先看执行器启动日志有没有 `register jobhandler success`——没有 → 注册侧问题（如本次 @RefreshScope）；有 → 是调度侧问题
- 调度侧问题通常是**多实例/脏地址**：旧进程没关、admin 执行器列表残留旧地址，任务轮询路由到没有该 handler 的旧实例。用 `netstat -ano | findstr <执行器端口>` 确认只有一个实例，admin 执行器管理里只保留一个在线地址
- 执行器配置 `ip:` 留空会自动获取本机 IP，若机器 IP 会变，建议固定 `ip: 127.0.0.1`
